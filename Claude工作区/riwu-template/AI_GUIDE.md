# 给接手 AI 的操作手册（GPT / Gemini / Claude 通用）

你的工作只有一件：**看图卡，填一份 `episode.json`**。不要改 `src/`、`scripts/`、`template/` 里的任何代码或参数；画风、节奏、动效、配乐都已经写死在模板里，改了就不是同一个系列。

## 1. 每期流程

1. 新建 `episodes/<编号>/`（例：`episodes/M007/`），把图卡放进 `episodes/<编号>/cards/`。原图只读，不裁、不改名以外的任何处理。
2. 先跑 `python3 scripts/grid.py episodes/<编号>`，在 `build/<编号>/grid/` 里得到每张卡叠了 0–1000 坐标网格的图（每 100 一条粗线带数字、每 50 一条细线）。**坐标从网格图上读，不要凭感觉估。** 某块看不清就放大：`python3 scripts/grid.py episodes/<编号> 03.png x1 y1 x2 y2`。
3. 照下面的格式写 `episodes/<编号>/episode.json`。
4. 运行 `python3 scripts/prepare.py episodes/<编号>`。
   - 有 `✖` 就按提示改框，重跑；
   - 有 `⚠ 压到了文字` 就把那个框放宽一点；
   - 打开 `build/<编号>/qc/lifts.png` 看每块抬出来的内容：字没被切、没混进别的栏、没带进照片或页眉。
5. 运行 `./render.sh episodes/<编号>`，等它出 `out/<编号>.mp4` 和 `build/<编号>/qc/report.md`。
6. 报告里有 `✖` 不算完成。打开 `qc/keyframes.jpg` 逐张看一遍，再交付。

## 2. episode.json 格式

坐标一律是 **0–1000 的比例坐标 `[x1, y1, x2, y2]`**（左上角为 0,0，右下角为 1000,1000），和图片实际像素无关。完整例子见 `episodes/_TEMPLATE/episode.json` 和 `episodes/M006/episode.json`。

```json
{
 "id": "M.007", "object": "物件中文名", "series": {"name": "日物图鉴", "tag": "MULTI LANGUAGE INDEX"},
 "bridge": "中", "anchor": "日",
 "cards": [
  {"file": "01.png", "role": "hook", "photo": [..], "subject": [..], "question": [..]},
  {"file": "03.png", "role": "lang", "lang": "日语", "short": "日", "photo": [..], "subject": [..],
   "word": "カップスリーブ", "reading": "かっぷすりーぶ · kappu suriibu", "meaning": "杯子的袖子",
   "parts": [{"t": "カップ", "m": "杯子", "link": "杯"}, {"t": "スリーブ", "m": "袖子", "link": "袖"}],
   "focus": [{"kind": "naming", "box": [..], "label": true},
             {"kind": "example", "box": [..], "label": true, "note": "例句里的「スリーブ」就是カップスリーブ的简称"}]},
  {"file": "06.png", "role": "outro", "photo": [..], "subject": [..]}
 ],
 "insight": "日、英、德：都把它叫作「袖子」", "insight_langs": ["日", "英", "德"], "insight_links": ["袖"]
}
```

| 字段 | 填什么 |
|---|---|
| `role` | `hook`＝封面提问卡（1 张）；`lang`＝某种语言的讲解卡；`outro`＝结尾互动卡（1 张）。其他图卡不要放进来 |
| `lang` / `short` | 语言名（2 个字，如「日语」）/ 一个字的简称（如「日」）。`short` 也决定名字字形：日→日文字形、韩→韩文、粤→港繁、繁→台繁，其余简体 |
| `photo` | 图卡上照片部分的框。**必须避开照片上压着的页眉、logo、页码、语言标签** |
| `subject` | 照片里**被讲的那个东西本身**（排气孔、吸汗带……）。模板会把它放进照片露出部分的中间 |
| `question` | 封面卡上那句大字提问的框，只框问题句 |
| `word` | **必填。**卡上最大的那个名字，**一字不差照抄**（冠词、长音、空格、大小写都照卡）。模板用字体重新排版，抄错就是错 |
| `reading` | 可选。卡上的读音/拼音/音标，照抄；卡上有两种（假名 + 罗马字）用 ` · ` 连起来 |
| `meaning` | 可选。字面意思，≤12 字，只能根据卡上写着的内容归纳；有 `parts` 时只在复盘里显示 |
| `parts` | 可选，强烈建议。把 `word` 拆成几段：`t` 依次拼起来（去掉空格）必须**等于** `word`（不等会报 ✖）；`m` 是该段意思（≤4 字，卡上写了才填，冠词等没意思的段填 `""`）；`link` 是跨语言共用的「意思代号」（一个汉字最好，如「袖」「汗」「孔」）|
| `focus` | 这一种语言要讲的重点框。默认最多：`bridge` 0 块、`anchor` 2 块、其他 1 块（多写的会被忽略，可用 `max_focus` 改）。`kind`：`def` / `example` / `why` / `usage` / `naming` / `extra` |
| `focus[].label` | 框里**没有**该栏小标题时写 `true`，模板补小标题 |
| `focus[].note` | 可选，≤26 字。面板下方一句提示，帮观众把这块和名字连起来（只能用卡上的信息） |
| `focus[].hide` / `cards[].hide` | 可选。`[[x1,y1,x2,y2], ...]`：框里夹着的小图标、不想要的半行，用周围底色盖掉 |
| `focus[].hold` | 一般不写，自动算。读不完时（报 ⚠ 阅读时间）优先**框少一点**，其次才写 `hold`（≤5.4） |
| `focus[].reflow` | 一般不写（默认重排）。重排后读起来不对写 `false` |
| `title` / `name` | v0.4 起**不需要**。只有卡上名字区有特殊信息（如别名）时才写 `name`，会多出一步原卡切片 |

### 跨语言关联（`link`）怎么填

- 同一个意思在不同语言里用**同一个 `link` 代号**。后面的语言出现前面已出现过的代号时，自动显示「又见面了 · 日 スリーブ」这样的行。
- 中文（`bridge`）可以拆 `parts`：拆了，后面的语言会显示「又见面了 · 排气 中」，观众用熟悉的中文对照（见 M005「排气/孔」）。只拆到有意义的段（2–3 段），拆太细会让后面每种语言多出好几行、变挤（M006 中文就没拆）。
- 只连**卡上能证明**的意思：英卡写 sleeve=袖子、德卡写 Manschette=袖口，才能都用「袖」。
- `insight_links`：复盘里要高亮的代号（就是 `insight` 说的那个意思）。不写时自动取出现 ≥2 次的代号。

## 3. 画框规则（最重要）

- 框要**包住整栏**：小标题＋正文，四周留一点空白，但不能碰到相邻栏、分隔线、照片、页眉。模板会自动把框收紧到实际文字上，所以宁可稍大，不要切字。
- 一栏一个框。不要一个框跨两栏（左右两栏的内容要分开框）。
- **例句只框一句**：一句原文＋它的中文翻译（一组），不要把整栏 2–3 个例句都框进来。字太多会被缩小、读不完。
- 重点块尽量在 6 行以内（重排后）。超过的，换一块更短的，或只框其中最有意思的一段。
- 每种语言挑**不同角度**的重点，不要每种都选同一种 `kind`：例句、命名逻辑、设计原因、使用场景轮流出现。挑这种语言**最有意思、别的语言没有**的那一块。
- **每块重点只留 1–2 句关键的话。**名字已经单独讲过了，重点块只补「为什么这么叫 / 一句例句」。阅读速度按 10 字/秒算，一块 5.4 秒最多约 50 个字；报 ⚠ 阅读时间就框少一点。
- `hide` 的坐标别估：用一小段 Python 读像素，沿行扫描墨迹（灰度 <140）的起止列，确认要盖的图标/半行的真实范围，再换算成 0–1000。
- 全片目标 40–46 秒：开场 4.2 + 中文 2.4 + 日语约 13–16 + 其余每种约 7–8.4 + 复盘 3.6 + 结尾 4.2。语言超过 4 种时，日语只选 1 块重点（`"max_focus": 1`）。

## 4. 顶层字段 `bridge` / `anchor` / `insight` / `insight_langs` / `insight_links` / `recall`

- `bridge`：过渡语言，默认 `"中"`。**最先出现**，只亮名字 2.4 秒（「你熟悉的叫法」），给观众一个已知的锚点。
- `anchor`：主角语言，默认 `"日"`。紧跟在 `bridge` 后面，名字停得最久、最多 2 块重点，最后有「还记得它叫什么吗？」回忆步（`"recall": false` 可关）。
- 其余语言按 `cards` 顺序，各 1 块重点。
- `insight_langs`：`insight` 说的是哪几种语言（简称列表）。复盘时这几行会亮金边、用金线连起来。

### `insight`（可选，但强烈建议）

复盘最后一行的「跨语言发现」，≤24 字。它是整期的价值所在（命名逻辑，而不是翻译对照表）。
要求：只用这几张卡上**写着的**信息归纳（例：日卡写了スリーブ=sleeve、英卡是 sleeve、德卡 Manschette=袖口 → 「日、英、德：都把它叫作「袖子」」）。归纳不出来就不写，不要硬凑。`meaning` 同理：卡上写了「sweat（汗水）+ band（带子）」才能写「汗 + 带」；日卡只写了「スベリ」没解释，就不写（不要用自己的知识补「滑」）。

### `format`（可选）：同一份 episode.json 出三种版式

- 不写 = `reveal`（讲解式）。`quiz`（猜选式）/ `flash`（快闪式）一般用命令行 `./render.sh episodes/<编号> --format quiz` 临时指定，不用改 json。
- **你不需要为 quiz / flash 多画任何框**。它们只用你已经填好的 `word` / `reading` / `parts` / `meaning` / `insight` 和照片框；所以这些字段一个字都不能错——猜选式会把主角语言的名字和**别的期**的名字并排给观众挑，快闪式只有名字没有讲解。
- 猜选式需要 `episodes/` 里另外至少 2 期有同一主角语言（默认日语）的 `word`；不够会报 ✖。会显示那两期的 `object`（物件中文名）作为「其实是 · …」，所以 `object` 要写成观众一看就懂的中文名。
- 可选 `"quiz": {"from": ["M.004", "M.006"]}`：只从这几期挑干扰项（例如避开和本期太像、会引起争议的名字）。

## 5. 画面安全区（模板已自动保证，改框时别破坏）

- 成片是原生 1080×1920：照片铺满上半屏、渐隐进纸面，面板直接落在纸上，没有「画中画」。
- 顶部 y<220 是平台顶栏，HUD 放在 y≈236；右侧 x>964 是点赞/评论按钮列；底部 y>1600 是标题文案区。
- `prepare.py` 发现面板越界会报 `⚠ 超出安全区`，这时把框收小（少框一两行）。

## 6. 不要做的事

- 讲解文字（`focus`）不要重新打一遍：模板只用原图像素。唯一要转写的是 `word` / `reading` / `parts[].t`，必须和卡上一字不差。
- 不要“纠正”图卡内容。发现可疑的写法，在交付说明里提一句就行。
- 不要改 `template/style.json`、动效、配乐、字体、时长上下限来“让检查通过”。检查不过就改框。
- 不要往 `cards/` 里放加工过的图。

## 7. 标准样例

`episodes/M006/episode.json` 是验收过的标准答案（咖啡杯套，中/日/英/德）。另有三期不同版式的样例：`episodes/M009`（防滑握套：含粤语，名字区左右两栏）、`episodes/M005`（杯盖排气孔：页眉压在照片上、主体很小）、`episodes/M004`（帽内吸汗带：标题居中、页眉在照片下方、有韩语）。新的一期照它的结构写。不确定框怎么画，就对照 `build/M006/qc/lifts.png` 看效果。
