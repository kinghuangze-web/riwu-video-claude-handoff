# **0. 如何使用本规范**

Codex 在接到任何“多语言版本 / M 系列 / 某物件多语详解”的任务时，先判断当前账号所处阶段，再决定封面入口、内容深度和发布方式。不得跳过阶段判断，直接把韩语、英语当作与日语同权重的新栏目。

|  |
| --- |
| **最短执行路径**  确认物件 → 查素材库与 M 编号 → 判断是否值得多语化 → 核验各语言真实名称与使用场景 → 选择桥接/深挖/独立阶段 → 规划 5-7 张图 → 写标题、简介、标签 → 更新素材库与发布状态。 |

# **1. 项目的上位定位**

当前账号名称仍为“日物图鉴”，但多语言项目的上位概念应理解为“日常事物的名字图鉴”。项目核心不是教日语，而是发现那些每天都能看到、每天都可能使用，却很少有人认真想过“它到底叫什么”的东西。

日语是最早建立起来的内容切口，也是当前最重要的用户基础。多语言扩张的目标不是给日语账号机械增加韩语和英语，而是在同一母命题下继续追问：同一个物件，在不同语言中叫什么？为什么这样命名？正式名称、日常名称、商品名称是否一致？

|  |
| --- |
| **多语言 ≠ 四语翻译表**  每一种语言都应达到原本日语单语内容应有的解释深度。四语并列只适合作为总结页，不应成为整篇内容。 |

# **2. 当前现实约束：现有受众几乎都是日语用户**

现有粉丝大多因为“这个东西日语叫什么”而关注。不能因为我们决定长期扩展多语言，就假设他们也会自然喜欢韩语或英语。纯韩语内容在现阶段可能同时面临旧粉丝点击意愿下降、账号既有内容标签与新内容不完全匹配两个问题。

因此，多语言扩张必须采用“渐进式用户迁移”，而不是“赛道突然切换”。

# **3. 三阶段迁移策略**

| **阶段** | **内容形态** | **封面入口** | **核心目标** |
| --- | --- | --- | --- |
| 阶段一：桥接期 | 日语仍是钩子，多语言是奖励 | 从日语已知信息带出韩语/英语 | 验证旧粉是否愿意接受“不同语言如何命名同一物件” |
| 阶段二：单语言深挖 | 整篇可讲韩语或英语 | 封面仍保留日语锚点 | 建立新语言内容习惯，但不切断旧受众入口 |
| 阶段三：独立语言期 | 允许纯韩语/纯英语专篇 | 可直接问目标语言叫什么 | 测试账号是否已形成“多语言日常物件图鉴”认知 |

## **3.1 阶段一：桥接期**

不大量发布“纯韩语”“纯英语”内容。日语继续承担旧用户的点击入口，多语言承担新的内容奖励。

• 推荐：这个东西日语叫 XXX，那韩国人 / 英语里又怎么叫？

• 推荐：日语和韩语为什么用完全不同的方法给它命名？

• 推荐：同一个不起眼的小东西，中日韩英居然有不同命名思路。

本阶段真正要验证的是：现有用户究竟只喜欢“日语”，还是喜欢“那些不起眼的小东西居然有名字”这个内容机制。

## **3.2 阶段二：日语锚点 + 单语言深挖**

当用户已经多次接触多语言内容后，可以制作韩语专篇或英语专篇，但封面仍保留旧用户能够理解的日语锚点。例如：“日语里叫○○，那韩国人平时到底怎么叫它？”

|  |
| --- |
| **职责分工**  封面负责继承旧受众；内页负责建立新语言内容。 |

## **3.3 阶段三：独立语言内容测试**

只有当用户已经逐渐形成“这个账号会研究不同语言如何给日常物件命名”的认知以后，才开始测试真正独立的“这个东西韩语叫什么？”“英语为什么把它叫 XXX？”并逐步减少日语作为入口的依赖。

# **4. 变量控制：现阶段不要同时大改**

多语言扩张期禁止同时大幅修改账号名称、视觉模板、语言比例、内容结构和发布节奏。否则一旦数据波动，将无法判断是哪一个变量导致。

| **变量** | **当前策略** |
| --- | --- |
| **账号名称** | 暂时继续使用“日物图鉴” |
| **账号简介** | 可先扩大定义，强调“从日语出发，看不同语言怎么称呼日常小物” |
| **视觉系统** | 继承原系列，只增加多语言识别层 |
| **内容比例** | 日语继续为主，多语言作为实验支线 |
| **发布节奏** | 尽量保持稳定，不与多语言测试同时大改 |

# **5. 系列架构与编号规则**

日语主系列继续使用 NO.001 / NO.002 / NO.003……；多语言系列使用 M.001 / M.002 / M.003……。

|  |
| --- |
| **M 编号的定义**  M 编号代表“物件”，不是代表某一篇文章。同一个物件可以有 OVERVIEW / JP / KR / EN 等多个子篇，但仍属于同一个 M 编号。 |

| **示例** | **含义** |
| --- | --- |
| **M.002** | 水龙头起泡器这个物件 |
| **M.002 / OVERVIEW** | 中日韩英比较总篇 |
| **M.002 / JP** | 日语深度篇 |
| **M.002 / KR** | 韩语深度篇 |
| **M.002 / EN** | 英语深度篇 |

Codex 必须维护：M 编号、中文物件名、已制作语言、未制作语言、发布时间、使用过的图片、是否发布、是否有后续深挖价值。禁止重复选题、编号冲突、同物件重复建号、旧素材被误当新素材。

# **6. 多语言选题筛选**

不是所有日语选题都适合直接多语化。优先选择同时满足多个条件的物件。

**1. 日常可见度高**：用户应产生“我天天见这个东西”，而不是“这是什么专业零件”。

**2. 中文里也很少有人知道正式名称**：天然具备“原来它有名字”的惊喜。

**3. 不同语言存在明显命名差异**：功能命名、形状命名、外来语、行业术语等差异越明显，越值得做。

**4. 正式名称与日常称呼存在差异**：可讲正式术语、消费者说法、电商词和行业词。

**5. 存在搜索、购买或维修场景**：用户看完后可能真正去搜索或使用，收藏价值更高。

|  |
| --- |
| **不建议深挖的情况**  如果四种语言只是机械音译，几乎没有真实使用差异或命名逻辑差异，则不应为了“多语言”强行做成深度专题。 |

# **7. 每个语言专篇的最低信息深度**

| **模块** | **必须回答的问题** |
| --- | --- |
| **标准名称** | 最准确、最常见的标准名称是什么？ |
| **读法** | 是否需要发音/罗马音？只有对理解有帮助时提供。 |
| **构词方式** | 名称由什么组成？功能词、形状词、外来语、汉字词、品牌泛化等。 |
| **命名逻辑** | 为什么这个语言选择从这个角度命名它？ |
| **真实使用** | 正式名称、日常口语、商品名、电商搜索词、行业名称是否不同？ |
| **使用场景** | 包装、电商、维修、家居、口语或技术资料中分别怎样出现？ |
| **相关词** | 仅在帮助理解时补充同词根、搭配、近义词或易混词。 |

视觉结构可以统一，但知识解释方式不能强行统一。日语可以重点讲汉字词、和制英语、外来语与简称；韩语可以重点讲固有词、汉字词、外来语与商品名；英语可以重点讲词根、功能命名、专业名与普通称呼、英美差异。

# **8. 标准图文结构：5-7 张**

图片数量根据内容实际决定，通常建议 5-7 张。不能为了凑模板强制固定。

| **页** | **任务** | **内容要点** |
| --- | --- | --- |
| **1** | 悬念封面 | 真实物件 + 中文问题；不公布答案；保留系列标识。 |
| **2** | 答案揭晓 | 目标语言名称、必要读法、中文解释、清晰实物。 |
| **3** | 为什么这么叫 | 词源、构词、命名逻辑，制造“原来如此”。 |
| **4** | 当地人真的这么说吗 | 区分正式名称、普通说法、电商词、行业说法。 |
| **5** | 相关使用 / 延伸 | 常见组合词、同类零件、搜索方式、使用情境。 |
| **6** | 总结 | 简洁复盘，不重复堆砌前文；显示 M 编号与同物件其他语言。 |
| **7** | 可选扩展 | 只有内容确实值得时再增加，不为了页数硬填。 |

# **9. 封面与标题策略**

封面仍然以中文普通用户能够立即理解的“物件问题”作为核心，不应先把外语词放到最前面。桥接期尤其要给旧日语用户保留点击理由。

| **阶段** | **推荐标题/封面方向** | **避免** |
| --- | --- | --- |
| **桥接期** | 日语里叫「XXX」，那韩国人怎么叫？ | “水龙头起泡器的韩语名称详解” |
| **单语言深挖** | 日语里叫「XXX」，韩国人平时到底怎么叫它？ | 完全抛弃旧受众入口 |
| **独立语言期** | 这个天天见的小东西，韩语到底叫什么？ | 标题变成课程式“韩语词汇学习” |

标题重点始终围绕“物件”，而不是围绕“语言学习”。

# **10. 视觉系统：70% 继承，30% 区分**

多语言系列不能重新建立完全不同的视觉系统。推荐“70% 继承日物图鉴，30% 用于识别多语言系列”。

| **必须继承** | **多语言新增** |
| --- | --- |
| **3:4 竖版；真实生活摄影；真实物件结构；中文主视觉；极简编辑排版；大面积留白；克制标注；相同字体、边距、信息层级。** | MULTI / LANGUAGE INDEX / M 编号 / JP·KR·EN 等小型语言导航；当前语言轻微强调。 |

|  |
| --- |
| **系列感 ≠ 复制画面**  同一个 M 编号下的不同语言篇，不要只换文字。JP 可用正侧面微距，KR 可用拆卸过程，EN 可用拆下后的零件陈列。设计系统一致，但构图与使用状态应变化。 |

不要滥用国旗。多语言栏目本质是“语言”，不是“国家旅游文化”。英语不等于美国。优先使用 JP / KR / EN 或 日 / 韩 / 英。

# **11. 简介 / 正文区的职责**

核心知识已经放在图片里后，简介不应复述图片内容。简介承担三个功能：说明为什么选这个东西；补充一个不值得单独占页的小观察；串联下一篇或下一语言。整体更像“编辑手记”。

|  |
| --- |
| **推荐语气**  同一个日常物件，换一种语言，会叫什么？这次想看的不只是一个翻译，而是这个名字为什么会出现、当地人平时到底怎么说，以及正式名称和日常名称有没有区别。 |

避免空泛 AI 句式，例如“语言不仅是沟通的工具，更承载着文化的温度”。除非内容确实需要，否则不使用这类泛化结尾。

# **12. 发布比例与节奏**

多语言扩张早期不能让多语内容淹没日语系列。建议初期仍以日语为主，每 3-5 篇日语内容中穿插 1 篇多语言实验内容，具体比例再根据数据调整。

禁止从“昨天全部是日语”突然切换成连续“韩语 → 英语 → 韩语 → 英语”。这会造成账号认知断裂。

# **13. 数据测试方法**

不能用一篇爆款或一篇扑街直接判断方向成立或失败。至少连续测试多个高日常认知、高好奇度、命名差异明显的物件。

| **样本** | **作用** |
| --- | --- |
| **A 类：纯日语基准内容** | 提供当前账号正常表现的参考线 |
| **B 类：日语主钩子 + 双语言** | 测试旧用户对跨语言比较的接受度 |
| **C 类：日语主钩子 + 多语言** | 测试更强扩展是否仍能维持点击与收藏 |

重点观察：点击/阅读表现、收藏、评论、分享、新增关注、首页推荐表现，以及新增关注的人群是否发生变化。

|  |
| --- |
| **真正要回答的问题**  不是“韩语有没有流量？”，而是“原有日语用户是否愿意跟随账号进入‘不同语言如何命名同一个物件’这个新母命题？” |

# **14. 进入纯韩语 / 英语阶段的条件**

只有当桥接型内容连续证明以下信号，才扩大纯语言专篇比例：

• 点击没有明显崩溃。

• 收藏与互动正常。

• 用户开始主动讨论其他语言。

• 新增关注仍然健康。

• 多语言内容不再被用户视为“跑题”。

如果桥接内容持续偏弱，先检查选题、封面、物件好奇度、语言差异价值、一次加入的语言数量，以及旧用户是否还有进入理由，不要立刻宣布多语言方向失败。

# **15. Codex 单期工作流**

**1. 确认物件具体是什么。陌生、微型或行业零件不得仅凭名称猜结构。**

**2. 检查素材库中是否已有该物件。**

**3. 检查是否已有 M 编号。**

**4. 检查哪些语言已经制作、哪些还未制作。**

**5. 判断该物件是否适合多语言：日常度、好奇度、命名差异、深挖价值。**

**6. 核验各语言可靠名称，不把少见术语误当普通口语。**

**7. 区分正式名称、日常称呼、商品名称、搜索词、行业术语。**

**8. 分析每一种语言为什么这样命名。**

**9. 找出语言之间真正值得比较的地方。**

**10. 判断当前账号阶段：桥接期 / 单语言深挖期 / 独立语言期。**

**11. 根据阶段决定封面钩子。**

**12. 规划整篇 5-7 张图的信息结构。**

**13. 规划每张图需要展示的真实物件状态。**

**14. 避免不同语言文章使用完全一样的画面。**

**15. 输出标题、简介、标签与下一篇衔接。**

**16. 更新多语言素材库、图片使用记录与发布状态。**

# **16. Codex 每次输出策划的标准格式**

☐ 基本信息：物件、M 编号、目标语言、当前阶段、是否首次出现。

☐ 为什么值得做：2-4 句话说明多语言价值。

☐ 不同语言核心差异：明确指出真正值得讲的差异；若无明显差异，应建议不做深度专题。

☐ 封面方案：中文问题句、系列标识、目标语言、封面画面、旧用户为什么仍愿意点。

☐ 图文结构：逐张写清信息任务和真实画面。

☐ 标题：至少给点击型、知识型、系列型三个方向。

☐ 简介：输出可直接发布版本。

☐ 标签：只给真正相关的标签，不机械堆“学习/涨知识”。

☐ 后续关系：说明下一篇最适合接什么语言或什么物件。

# **17. 绝对禁止事项**

• 把多语言项目理解成简单四语翻译。

• 因为是多语言就弱化物件本身。

• 桥接期突然连续发布大量韩语或英语。

• 桥接期完全抛弃日语入口。

• 为了栏目统一强迫每种语言讲完全相同内容。

• 为了凑页数加入空洞知识或无关词汇。

• 大量使用国旗制造“国家旅游感”。

• 把英语默认等同美国。

• 完全重做视觉风格，破坏主页系列感。

• 同一个物件不同语言直接复制同一组图片。

• 不检查素材库就生成新编号。

• 把正式名称当成日常口语，或把少见术语包装成“当地人都这么说”。

• 没有依据时自行猜词源。

• 只因为一个词存在就硬做一期。

• 使用“语言承载文化”“世界更加丰富”等空洞 AI 文案作为固定结尾。

# **18. 最终自检：一篇多语言内容是否合格**

|  |
| --- |
| **四项同时成立才值得进入多语言系列**  物件值得看；名字值得知道；为什么这样命名值得理解；换一种语言以后又产生了新的观察。 |

☐ 如果把所有外语词删掉，这个物件本身是否仍然有兴趣点？

☐ 如果把所有图片换成词汇表，内容是否会明显失去价值？如果不会，说明只是翻译表。

☐ 是否清楚区分了正式名称、日常称呼、商品名和搜索词？

☐ 是否解释了“为什么这样命名”，而不是只做 A=B？

☐ 桥接期是否仍然给旧日语用户保留了点击理由？

☐ 同一 M 编号下不同语言是否保持系列感但避免画面复制？

☐ M 编号、素材使用和发布状态是否已更新？

# **19. 长期品牌方向**

短期：日物图鉴仍以日语为主，多语言作为支线。中期：让用户逐渐理解，日物图鉴不只是日语单词账号，而是在研究那些“每天都能看见，却不知道叫什么”的日常物件。长期：如果多语言验证成功，再考虑把品牌母命题升级为更适合“日常物件 × 名称 × 语言 × 命名方式”的名称。

品牌升级必须建立在用户认知已经发生变化之后，不为了理念完整提前牺牲已经建立起来的用户资产。

# **20. 给 Codex 的最终总则**

|  |
| --- |
| **必须长期记住**  我们不是在给日语账号增加韩语和英语。我们真正做的是：从“这个东西日语叫什么”，一步一步升级成“原来这个不起眼的小东西，在不同语言里都有自己的名字，而且每一种语言看待它的方式还不一样”。 |

**日语是入口。**日常物件是主体。名字是知识钩子。不同语言的命名逻辑，才是多语言系列真正新增的价值。
